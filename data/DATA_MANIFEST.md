# Data Manifest — TEP-ARP (Paper 37)

All catalogue values and measurements used by the pipeline are obtained
from the public archives listed below; nothing in `data/` is fabricated
or hand-entered beyond the published literature seeds in
`step_00_arp_pair_catalog.py`, each of which is verified against NED in
`step_01` before use.

## External sources queried at runtime

| Source | Service | Used by | Contents |
|---|---|---|---|
| NASA/IPAC Extragalactic Database | NED (astroquery) | steps 01, 05, 20, 27 | object names, redshifts, positions, diameter/PA tables |
| Simbad | CDS (astroquery) | steps 01, 20 | name resolution, positions, redshifts |
| SkyView | GSFC (astroquery) | step 02 | DESI Legacy DR10 / SDSS / DSS imaging |
| VizieR VII/290 (Milliquas v7.2) | CDS | steps 22, 23, 24, 27 | quasar catalogue, class flags (Q/A/B/K/X) |
| VizieR J/ApJ/944/94 (Cosmicflows-4) | CDS | step 05 | redshift-independent host distances |
| VizieR J/ApJS/199/26 (2MRS) | CDS | step 24 | forward galaxy–quasar cross-correlation |
| VizieR J/AJ/149/171 (Tully 2MASS groups) | CDS | step 25 | satellite redshift asymmetry parent sample |
| NED diameters / HyperLEDA (VII/237) | NED / CDS | step 27 | host photometric PAs and axis ratios |
| ESO Science Archive | astroquery.eso | steps 28, 29 | MUSE, VIMOS, SINFONI, GIRAFFE frame metadata; UVES/X-shooter/FORS2 coverage |
| MAST | astroquery.mast | steps 28, 29 | JWST IFU, MaNGA, fiber, HST coverage; HST/COS, STIS, FOS, IUE, FUSE, GALEX spectra |
| Keck Observatory Archive | KOA TAP (pyvo) | step 29 | HIRES, ESI, LRIS spectroscopic coverage |
| SDSS | astroquery.sdss | step 29 | spectroscopic coverage of companions |

## Layout

- `data/raw/` — downloaded raw products (large `.dat` files kept
  compressed; see `.gitignore`)
- `data/interim/` — scratch space (empty except `.gitkeep`)
- `data/processed/` — pipeline-produced tables committed for
  reproducibility; every file is regenerated by a numbered step

## Provenance

`results/outputs/pipeline_run_manifest.json` records the package
versions, git commit, and timestamp of the most recent run. Per-record
provenance (program IDs, object names, archive, query status) is stored
inside the processed tables themselves — e.g.
`archive_kinematic_audit.csv` carries `science_programs` and
`science_objects` for every in-cone frame.
